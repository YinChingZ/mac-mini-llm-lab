# 交换机与学校网络：配置方案与测试计划

2026-10-30，草案。前提：交换机接入后，学校网络可能给每台分配具体的 IP；具体情况到时再定。本文给出**按情况选择的配置**和**测试计划**。测试脚本 [`scripts/netprobe.sh`](../scripts/netprobe.sh) 只读：不改任何设置，不读取钥匙串，不带密钥或账号，也不调用模型。项目背景见 [PROJECT-BRIEF.md](PROJECT-BRIEF.md)。

**总原则**：七台机器中有六台与另一个项目共用，对方运行期间（至 2026-11-03 09:00）这六台只允许做 T0（只读快照）；需要接线或改网络设置的步骤，先在 DM7 上试点，共用方运行结束后再推广。

---

## 1. 学校网络可能出现的五种情况，各自怎么配

| 情况 | 识别方法（netprobe） | 配置 | 对 LLM 集群的影响 |
|---|---|---|---|
| **S1 DHCP 自动分配，同一子网** | `if_en0_dhcp_server` 有值，七台 IP 在同一网段、掩码相同 | 网络设置保持“使用 DHCP”。如果学校支持，请求按 MAC 绑定固定租约 | 最理想。机器之间的流量走我们自己的交换机（二层），不经学校核心网 |
| **S2 学校给每台指定静态 IP** | 学校发 IP/掩码/网关/DNS 清单 | 系统设置 → 网络 → 以太网 → 详细信息 → TCP/IP：选“手动”，填写 IP、子网掩码、路由器；DNS 一栏填学校给的 DNS。**IP、掩码、网关三项必须一起改对**（PDF 第 10 章也这样提醒） | 同 S1。注意七台是否在同一子网，不在则见 S4 |
| **S3 需要先登记 MAC 地址** | 接线后拿不到 IP，或拿到 169.254.x.x | 先用 T0 收集每台以太网口的 MAC（只读，现在就能做），交给学校登记 | 登记前无法上网；七台之间仍可用自分配地址互通，但不建议依赖 |
| **S4 七台被分到不同子网，或学校交换机开启终端隔离** | `peer` 模式：ping 不通、或 `hops` > 1 | 请学校把七个端口划进同一 VLAN 并关闭端口隔离。也可以在我们自己的交换机上另起一个私有网段（见 §3） | 机器之间流量绕经学校路由器，或直接被拦截，MLX 多机推理无法运行，或明显变慢 |
| **S5 门户登录或 802.1X 认证** | `captive_portal=SUSPECTED`；或接线后提示输入账号密码 | 门户或 802.1X 的**账号和密码只能由本人输入**，不要写进脚本或日志。认证会过期的话，长跑任务会中断，需向学校申请设备白名单 | 认证过期等于断网：对依赖外网的长时间任务是致命的，对 LLM 推理影响较小（机器之间互访仍可走二层） |

**另外必须查清的出口条件**
- **能否访问 Hugging Face / PyPI / Homebrew / GitHub**：LLM 实验需要下载约 30–85 GB 的权重，Codex 需要 GitHub。若 Hugging Face 不通，按 PDF 第 15 章：在一台能访问的机器上下载同一冻结版本，校验后再拷贝，不换成“名字相似”的模型。
- **共用机器上其他项目依赖的外部服务**：由对方项目自行确认；需要时可用 `PROBE_EXTRA_URLS` 让 `netprobe.sh egress` 额外检查指定地址。

## 2. 测试计划

### T0：只读快照 —— 现在就可以做，七台全部（对共用机器的运行也安全）
```
bash scripts/netprobe.sh snapshot
```
采集：各端口名称、设备名和 **MAC 地址**（学校登记要用）、网络服务顺序、默认路由走哪个接口、各接口的 IP、掩码、网关、DNS、系统代理和防火墙状态。只运行系统读取命令，耗时约 1 秒。

**目的**：①提前把七个 MAC 交给学校；②确认共用机器当前的默认路由确实是 Wi-Fi，用来对比以后的变化。

### T1：DM7 试点 —— DM7 接上学校交换机之后
1. 接线前跑一次 `snapshot`，接线后再跑一次，对比默认路由是否切换到以太网、拿到的地址、网关和 DNS。
2. `bash scripts/netprobe.sh egress`：
   - 门户检测；
   - DNS 解析 `huggingface.co`；
   - 对 GitHub、Hugging Face、PyPI、Homebrew（及 `PROBE_EXTRA_URLS` 指定的地址）各发一次**不带凭据**的 HTTPS 请求，记录状态码与 DNS/TCP/TLS 各段耗时；
   - 20 次 Hugging Face TLS 握手耗时，与 Wi-Fi 下的同一测量对比；
   - 1500 字节 MTU 是否通。
3. **通过标准**：门户为 `none`；各站点返回任意 HTTP 状态码（不是 000）；TLS 握手 20 次中 0 次失败；MTU 通过。
4. 不通过时按 §1 识别属于哪种情况，带着结果找学校。

### T2：全集群 —— 共用方运行结束之后（至少 2026-11-03 09:00 之后）
1. 其余六台接线（DM5 搬入），各跑 `snapshot` 和 `egress`，标准同 T1。
2. 在 DM7 上运行 `bash scripts/netprobe.sh peer <其余六台 IP>`：丢包为 0，`hops` 为 1（同一二层），22 端口状态（开启远程登录后应为 open），mDNS 能否发现主机（看不到就在 hostfile 里全部用 IP）。
3. 装好 iperf3 后，按 PDF 第 14 章测相邻机器的双向带宽。**通过标准**：同一交换机上应接近 940 Mbit/s；低于约 600 Mbit/s 先查是否走了学校核心网，或者某根线只协商到百兆（`if_en0_media` 会显示 `100baseTX`）。
4. 记录七台最终的 IP，填进 PDF 第 10 章的表格，用来生成 hostfile。

## 3. 推荐的目标配置（共用方运行结束后）

1. **一个端口一台机器，同一子网**（S1/S2）。七台的 IP 用 DHCP 固定租约或学校指定的静态地址，不用会变的地址。hostfile 全部写 IP。
2. **服务顺序**：LLM 实验期间，以太网排第一（推理要走有线）。Wi-Fi 可以保留作为管理后备，也可以关闭以免路由混乱。
3. **只给集群用的私有网段（可选的优化，适用于 S4，或学校只给一个 IP 的情况）**：在我们的交换机上给七台的以太网再加一个手动地址（例如 `10.77.0.1`–`10.77.0.7/24`，不设网关）。上网继续走学校分配的地址或 Wi-Fi，机器之间的 MLX 流量走 10.77 网段，完全不经学校网络。macOS 不能直接在同一个以太网服务上同时用 DHCP 和手动地址，做法是在“网络”里**复制一个以太网服务**（同一物理口），一个用 DHCP 或学校静态地址，另一个用 10.77 手动地址。复制后要用 `peer` 再测一遍。
4. **安全**：远程登录和屏幕共享只允许 lab 账户使用；不在路由器上做端口转发；8080 模型服务只在本地网段内访问（PDF 第 11 章）。防火墙保持开启，只在弹窗时允许实验 Python 接收连接。
5. **对共用机器的保护**：如果学校坚持在共用方运行结束前就给这些机器接线，先把它们的服务顺序调成 **Wi-Fi 在以太网之上**，再插线。这样插线不会把默认路由抢到以太网，在途的网络调用不受影响。这一步也是改设置，需要机器所有者本人操作并记录。前提是 Wi-Fi 和有线不在同一子网。

## 4. 需要你或学校提供的信息

- 学校对每个端口是 DHCP 还是指定静态地址；如果是静态地址，给出七组 IP/掩码/网关/DNS。
- 是否需要登记 MAC（T0 输出里有）、门户登录或 802.1X。
- 七个端口是否在同一 VLAN，是否开启了端口隔离。
- 出口是否允许 `huggingface.co`、`github.com`、`pypi.org`、`formulae.brew.sh`，是否需要代理。
